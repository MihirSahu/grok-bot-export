# Grok Vault

A browser-authenticated macOS CLI for archiving all retained Grok Bot conversation text into Markdown for Obsidian. One account, all discovered bots and sessions, and no total message/page cap. It never reads the desktop app's data or credentials.

**Export behavior:** the CLI publishes after two matching full-account scans, including repeated bot/session inventories and every raw history page. If a gateway-only box bot's session list returns HTTP 404, its default history is exported and its additional-session coverage is marked **unverified**. Other source errors and changing reads prevent publication. The service does not provide an atomic snapshot or a guaranteed complete retention boundary; the CLI and `_export.md` report these limits explicitly.

See the [PRD](grok-bot-obsidian-exporter-macos-prd.md) and [implementation status](docs/implementation-status.md) for the remaining release gates and evidence.

## Build and run

Requires Apple Silicon macOS and exactly Bun **1.4.2**, revision **744846f84**. macOS 13 is the intended minimum; validation so far covers the current development Mac only.

```sh
bun --revision
bun install --frozen-lockfile --ignore-scripts
bun run check
bun run build
bun run verify:binary

./dist/grok-vault --help
./dist/grok-vault export "/absolute/path/to/existing/Obsidian Vault"
```

The standalone executable bundles its dependencies; users do not need Bun installed. Build output includes `SHA256SUMS`, toolchain/build metadata, and binary verification results. This is an unsigned development artifact, not a signed/notarized release.

The command opens the provider's browser sign-in. Complete sign-in there, or press Ctrl+C to cancel. Credentials remain in process memory. Grok Bot need not be installed or running locally. The validated cloud connection requires the account's cloud box to be running; the exporter never creates or wakes it. Browser sign-in and source reads need network access.

`--help` and `--version` are the only flags. The normal exit codes are `0` for a published observed export (including any explicitly reported session-inventory uncertainty) and `1` for any failure. Help/version also return `0`. Diagnostics contain authored explanations and counts, not message text, credentials, server error bodies, or signed URLs. A committed write transaction is recovered before new authentication; recovery is reported separately if the subsequent source read fails.

## Archive behavior

Output lives beneath `<vault>/Grok Bot`. Each bot receives a stable directory; the default session has daily notes there, while other sessions use `Sessions/<name — stable-id>`. `_export.md` records the single account, empty conversations, counts, observed boundaries, and per-bot session-coverage evidence. Notes and the manifest use `coverage: observed-retained-history`; the manifest lists every bot whose additional sessions could not be verified and records two matching scans without claiming an atomic snapshot. Reserved names, Unicode/case collisions, and unrelated paths are handled without overwriting unrelated files.

Text remains byte-for-byte intact after source decoding, including empty messages and embedded Markdown. Timestamps use the archive timezone recorded on the first export. Missing timestamps go to `_undated.md`. Content offsets and hashes, rather than Markdown headings, identify messages. Reference links/footnotes share a note namespace; unclosed fences and HTML can affect later messages. Text preservation takes precedence over isolating Markdown rendering.

An unchanged snapshot leaves generated bytes and mtimes unchanged. Missing old messages, source rewrites, manual edits, failed history reads, and unsupported attribution prevent a new transaction. Publication is atomic per file; readers can temporarily see mixed generations. Do not edit or sync managed files while an export is running. The OS lock coordinates exporter processes, and durable staged bytes recover an interrupted committed transaction without the source being available.

Exported notes can contain sensitive conversations. Staged files use mode `0600`, new directories use `0700`, and configured Obsidian/vault sync may separately transmit your notes.

## Manual recovery

1. Prefer restoring the exact original generated file from a trusted backup. Do not edit its hash to accept changed content.
2. If a committed `.grok-vault-transaction` exists, rerun to recover it at the original output root first. A conflicting target must be restored to its exact expected old or intended new bytes; preserve every staged payload when blocked. Never delete or move a journal to bypass a conflict.
3. If exact restoration is unavailable and no committed transaction remains pending, stop every exporter and external writer. Verify a backup of the **entire** `Grok Bot` root, then move that root intact outside the destination. A later successful observed export can create a fresh root. This preserves the old notes, manifest, lock, residual artifacts, manual edits, and unrelated files together. Deleted source history remains only in the old backup and is not automatically reimported. The fresh archive captures its timezone again.

There is no automatic reset. Do not delete or rename one managed note, move only one agent directory, or unlink the lock file. Unknown staging/cleanup residue is preserved rather than automatically removed. Empty cleanup residue after an interrupted final cleanup is inert.

## Runtime isolation and development

The binary disables `.env`, `bunfig.toml`, `package.json`, and `tsconfig.json` autoload using [Bun's compile settings](https://bun.com/docs/bundler/executables#automatic-config-loading). Run it with **`BUN_OPTIONS` and `BUN_BE_BUN` unset**. These runtime overrides can execute before application code and are outside the supported environment; the isolated binary check demonstrates both behaviors with synthetic files.

The implementation separates `src/source`, `src/normalize`, `src/render`, `src/export`, `src/cli`, and `src/diagnostics`. Tests use authored synthetic conversations and temporary directories, never the user's real data. Build and test commands use only synthetic data and do not sign in. `scripts/validate-browser-source.ts` is an optional, explicitly invoked read-only live check; it is not bundled into the CLI. Account-specific research artifacts are excluded from the public repository.

Native `flock` and `renamex_np(RENAME_EXCL)` come from the system library through Bun FFI. The test suite exercises them on the host Mac along with publication interruption and replay. A broader final-artifact network trace, Obsidian rendering inspection, real long-history/blob/participant cases, macOS 13 validation, and signing/notarization remain release work.

## Repository privacy

Keep real exports outside the checkout. `.gitignore` excludes `Grok Bot/`, recovery payloads, local research/captures, environment files, credentials, signing keys, logs, and generated output. Source code, the lockfile, documentation, and authored synthetic tests belong in Git. Run `bun run check:public` before committing; it checks both current files and staged content for common credential patterns and accidentally included exports. Git history and commit author emails need separate review before changing repository visibility.
